# Threat Model

> **万一リポジトリが漏洩しても、外に出るのは「無害化したうえで意図的に残した情報」だけ——第三者や勤務先の生データは決して含まれない状態を守る。**

## 守るべき資産

- オーナーの私的な振り返りと自己モデル
- 第三者のプライバシー
- 勤務先・顧客・ベンダーの機密情報
- 認証情報（パスワード・トークン・鍵など）
- 保護対象の原本を特定できてしまう出典・来歴情報
- 画像や文書に含まれるメタデータと写り込んだ識別子

## 主なリスクと対策

| リスク | 起きうる問題 | 主な対策 |
| --- | --- | --- |
| **1. 誤コミット** | 生メモ・エクスポート・スクショ・認証情報・個人識別子が Git 履歴に入る | ローカル隔離（`.quarantine/` / `_local/`）、自動テキスト検査、正本化前の匿名化・メディア無害化、ローカル安全チェック（[privacy-ingress.md](privacy-ingress.md)） |
| **2. 公開設定ミス** | private repo を誤って public にする、または公開先へそのままコピーする | 個人の記録を置くリポジトリは恒久 private 扱い。公開が必要な場合は無害化した別派生だけを使う |
| **3. コネクタ / AI の過剰収集** | AI が学びの保存に必要な範囲を超えて原本を大量にコピーする | `AGENTS.md` の書き込みゲート、原本ではなく教訓を残す方針、人間レビュー必須、classifier は候補提示のみ |
| **4. メディア経由の漏洩** | 画像から氏名・顔・アカウント情報・社内 UI・GPS・端末情報が漏れる | 無害化派生のみ commit、EXIF/GPS 削除、`assets/` と `media/` の分離、目視確認ゲート |
| **5. 認証情報の漏洩** | API キーやパスワード等がリポジトリに入る | CI の機密スキャン、GitHub Secret Scanning / Push Protection（利用可能な場合）、漏洩時の即時ローテーション |

### ローカル安全ゲートの境界に関する補足

ローカル CLI の `--owner-approved` と gitignore 対象の `approvals.jsonl` は **運用上のレビュー記録** であり、暗号学的な本人認証ではありません。

- オーナーと同じローカル権限を持つエージェントは、技術的にはフラグ付与やファイル編集ができてしまいます。そのため最終的な防衛線は **オーナー自身の確認と PR 差分レビュー** です。
- ローカルゲートは外部コネクタによる GitHub Issue 直接作成を遮断できないため、Issue 作成前の確認ルールを別途徹底します。

## 信頼境界（Trust Boundaries）

```text
[非信頼 / 未レビュー]
外部アプリ・エクスポート・会話ログ・業務システム・スクリーンショット
        │
        ▼
  ローカル隔離のみ（.quarantine/ 等）
        │
        ▼
  privacy classifier（助言のみ）
        │
        ▼
  無害化候補の作成（redact / anonymize / abstract）
        │
        ▼
  ★ 人間レビュー（ここが信頼境界の通過点）
        │
        ▼
[信頼済み正本]
Git Markdown + レビュー済み assets/
        │
        ▼
[派生物]
グラフ・埋め込み・閲覧 UI・公開用派生
```

- classifier はあくまで助言であり、**信頼境界を越える権限は人間レビューだけ** にあります。
- 派生システムが正本の書き込みゲートを迂回してはいけません。
