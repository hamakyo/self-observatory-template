# Self Time Volume プロトタイプ

採用済みの Git 履歴（first-parent 順）に沿ってスナップショットを重ね、同じノート ID の連続した出現を線（worldline）でつなぐ任意の探索ビューです。  
位置や距離から心理状態・重要度・因果関係を推測するものではありません。


## 1. API 契約（`GET /api/time-volume`）

### パラメータ

| パラメータ | 既定値 | 上限 / ルール |
| --- | --- | --- |
| `from` / `to` | `to` = 索引済み head、`from` = `to` から遡った `snapshot_limit` 件 | 完全な正本 SHA。逆順の範囲は拒否 |
| `focus` | なし | 表示件数上限に達したときでも優先して残す stable ID |
| `snapshot_limit` | 24 | 最大 48。超過範囲は末尾の連続時点だけ残し、省略数を `coverage` に返す（間引きはしない） |
| `note_limit` | 60 | 最大 120。`focus` を先頭に辞書順で選ぶ（重要度順ではない） |

- 各時点（slice）の明示的関係は最大 240 本まで返します。
- 応答にはタイトルと状態メタデータのみを含み、**ノート本文は含みません**。
- ID 件数は省略された古い範囲ではなく、返却区間とその直前のベースライン（削除マーカー判定用）を対象に数えます。
- 応答には `from_sha`、`to_sha`、`coverage`（除外・省略数）、`parser_version`、`classification_version`、`layout_version` を含みます。

### 点の状態（イベント種別）

各 slice はコミットの独立した Self / Observatory 分類を保持します。ノートごとの点は次の 6 状態で表します。

| 状態 | 意味 |
| --- | --- |
| `added` | 新規追加（真の root 以外の取得境界は追加とみなさない） |
| `modified` | 更新（移動・改名を含む） |
| `newly superseded` | 新たに `superseded` になった |
| `deleted` | 削除。直前 slice のメタデータを使い、worldline を終端させる（再登場時は新しい線を開始） |
| `unchanged` | 変化なし |
| `unavailable` | 解析エラーや重複 ID で除外されたため読めない状態（診断と除外件数は表示し続ける） |

> これらは保存・索引化されたモデル上のイベントであり、人間本人の変化を直接断定するものではありません。

### 固定座標（X / Y）のルール

- 索引構築時に、各 ID が履歴に初めて現れた時点で整数の X / Y 座標を割り当てます。
- 新しい ID は、すでに配置済みの明示的関係（隣接ノード）に近い空きセルに配置します。同点時は決定的な ID・セル順で原点に近いセルを優先します。
- **一度決まった座標は動きません**。後続のノート追加、削除、表示範囲・focus・関係・レイヤーの絞り込みでも再配置しません。
- 同じ first-parent 履歴・同じ parser / layout 版で再構築すれば同じ座標が再現されます。
- カメラ合わせには全体の X / Y 範囲を使うため、範囲や focus でカメラ基準がぶれません。
- 座標の距離やカメラ回転時の見かけの動きに意味はありません。
- shallow clone では履歴が欠けているため、履歴を深くすると座標が変わることがあります。比較時は `coverage` と各バージョンを確認してください。

### レイヤーと操作

- **Self レイヤー**：ノート平面と worldline を描画します。
- **Observatory レール**：コミット分類だけを表示します（`Both` は両方に表示）。ツール変更のみのコミットから Self 変化イベントは生成しません。
- **Interpretation Shift**：現行索引からは推定できないため、マーカーを捏造しません。
- **操作性**：点のクリックと同じ操作をフォーム・キーボードからも行えます（回転・ズーム・リセット、前後 slice 移動、タイムスライダー、表示中ノート一覧、worldline の時系列イベント一覧）。
- **既存ビューへの導線**：選択した点から、そのままの SHA / ID で Browse・Provenance・Self Diff を開けます（`deleted` / `unavailable` 点では直前の有効版 `read_sha` を開けます）。
- **状態管理**：範囲・レイヤー・関係種別・選択 ID・選択 slice は URL に保持します。カメラ状態はローカル一時状態です。自動再生や慣性アニメーションはなく、`prefers-reduced-motion` を尊重します。

## 2. 描画方式と制約

- React 内の **平行投影 3D-to-SVG** で描画します（WebGL 不要、キーボード操作と DOM 検査が可能）。
- **X / Y** は ID ごとの固定座標、**Z** は採用順（コミットごとの等間隔であり、実経過時間ではない）です。
- ワイヤーフレームの探索面であり、不透明面の隠面消去や GPU 描画は行いません。精読は既存の 2D ビューを使います。
- 外部サービス・グラフ DB・正本への新フィールドは追加しません。
- 使い捨ての `note_layout` テーブルは index v6（`layout v1`）で導入されました（現在は index v7）。更新時は `uv run self-observatory index --rebuild` を実行してください。`layout_version` 不一致の旧索引は拒否されます。
- force-push・履歴の深化・parser / layout 規則の変更で配置が変わることがありますが、描画位置の変化を自己の変化として記録してはいけません。

## 3. 合成データでの性能実測

- 測定日：2026-09-25（ローカル macOS / Chromium 153.0.8010.12 / 1440×1000 / reduced motion 有効）
- データ：架空の 120 コミット × 240 ノート ID（編集・置換・削除と再登場・明示関係・Observatory のみ更新を含む。本人データは未使用）

| 測定項目 | 結果 |
| --- | --- |
| 120 スナップショットの索引再構築 | 6.99 秒 |
| 温かい API リクエスト（20 回） | 中央値 73.89 ms / p95 82.85 ms |
| 画面遷移〜描画完了（5 回） | 中央値 242 ms / p95 262 ms |
| キーボード回転〜描画完了（20 回） | 中央値 51 ms / p95 67 ms |
| 既定の返却シーン | 連続 24 時点 × 60 ID（1,440 点） |
| SVG 要素数 / JSON サイズ | 12,843 要素 / 955,931 bytes |

### 実測の前提と限界

- API は 120 コミット全体を走査したうえで末尾 24 時点に制限し、省略数（96 時点・180 ID・12,960 関係）を報告しました。
- ブラウザ測定は Playwright 入力＋2 アニメーションフレームを含み、GPU の FPS 測定ではありません。また、ブラウザコンテキストとローカルサーバーを再利用した温かい状態です。
- これらの数値は **上限付きプロトタイプとしての妥当性** を示すものであり、無制限の描画や既定画面への採用を正当化するものではありません。過密なシーンでは ID 選択・関係フィルター・範囲の絞り込みが必要です。

### 再現手順

```sh
pnpm build
pnpm exec playwright install chromium
pnpm benchmark:volume
```

使い捨ての合成 Git リポジトリを作成し、ポート 8018 のローカルサーバーで API・ブラウザを測定して自動終了します。結果とスクリーンショットは gitignore 対象の `_local/time-volume-benchmark.*` に保存されます。  
索引と API だけ測る場合は `uv run python scripts/benchmark_time_volume.py` を実行してください。
